# 从案件问题到检验结果

## 1. 明确任务与证据层次

记录交付物、案件期间、对象、已确认的委托要求、获准模板、材料存放地及允许使用的环境。区分：
- 背景：案情说明、拘留或逮捕文书、既有研判、讯问笔录等，标出其记载者和待核事项。
- 资金检材：实际取得并登记的电子文件、介质、反馈及完整性证明。
- 辅助材料：开户身份说明、主体名册、合同等，记录其证明用途，不一概视为资金流水。
- 程序材料：委托书、事项确认书、受理及审批、人员机构资格、签章和送达记录。

这些类别按实际作用登记，可以互相引用，不能互相替代。先阅读全案有关内容，再确定哪些资金问题能够解决侦查文书中的具体疑问；不要把文件目录直接改成鉴定要求。

## 2. 构建具体事项

每项包括：问题编号、对象及账卡号清单、起止日期、收付方向、统计指标、纳入/排除规则、需要的来源、可回答的证明问题、确认状态。采用 [事项矩阵](../assets/issue-matrix.csv)。

例如：“检验甲公司A账户于某起日至某止日向乙账户支付的笔数及金额；检验乙账户收到款项后至某日的收付款金额及余额。”这是两个可核查问题，后一项不预设资金专属来源。

可按案情选择公司间转付、个人与公司往来、支付结算、平台入出金/成交、系统发放、项目收退或支出摘要检验。不要固定套用八项，也不要要求每案都核定募集、获利和损失。对能查清的款项作明确结果；未能完成的事项写明止于何种记录、缺少何项关键证据及对结论的影响。

若是拟定委托事项，标为“建议/待确认”；已有真实委托则核对范围。延长期间、增加账号、改变统计口径会改变实际检验范围，应另列扩展建议并供机构确认，未确认前可作为另列分析结果，不能悄悄并入原正式范围。

## 3. 登记、保全与读入

为介质和电子文件分别编号。记录原文件名、原路径、提供方、获取/接收方式与时间、文件类型、字节数、完整性验证值、载体及流转记录。来源缺失如实登记。

- 确保原件不被编辑；工作副本与结果在独立目录，复制后逐项比对哈希。
- 加密文件与已解压文件分别编号、哈希和标状态。找到明文不等于已证明它由该加密原件导出。
- 同名不同版本、相同内容不同路径分别登记；根据实际版本来源选用，不按修改时间猜哪个是原始版。
- Excel 的重复表头、合并单元格、隐藏表、公式/缓存、日期序号、负值和文本账号需核查。账号按文本，保留前导零；无法恢复的精度损失不能用猜测修补。
- PDF/OCR的关键数值、账号、日期和表头回看页图。不得自动执行检材内宏、脚本、外链和笔记本。
- 仅做本地文件复制，不写成已经封盘、镜像或正式交接。

可使用 evidence_manifest.py 对明确目录生成和复核清单，适用范围见 [数据契约](data-contract.md)。

## 4. 清洗并保留血缘

保留原字段、原值和源文件/工作表/物理行号；规范字段另建。每条转换应可解释、可回到原行。

对重复文件/重复行、镜像转账、异常状态、失败与冲正分开标记。疑似重复不得直接丢弃；确认后保存规则、被保留项、被排除项及依据。生成有效数据、异常数据和操作记录，并核对：
原读取行数 = 纳入行数 + 排除行数 + 待核行数。
此处各集合必须互斥；合并多行时另外登记原行到规范行的映射，不能把“规范行数”直接放入等式。

按账户分别核验总体反馈期间、原始收付标志、正负金额、余额连续性和交易状态。仅有限日期明细时，不称全账户完整。金额和方向无法确定的记录隔离待核，不强制补齐。

## 5. 统计、勾稽与形成证明链

每项都依“源记录→纳入规则→检出明细→精确汇总→过程表→结果”推进。使用 [资金语义](fund-semantics.md)，在能够对应的位置核查付款端、收款端和系统/平台端。只有一侧资料时仍可检验该侧记录，但结论身份须明确。

复算不以主稿里的合计数字为输入；从选定原始记录重新得到数量、方向、金额与交叉关系。关键账号用“按账号检索”及“按户名检索”的差异结果补查，尤其关注空白户名、曾用名和多个卡号。不要用另一张已经整理过的同源汇总表充当独立原始证明。

## 6. 编制、同步和归档

按 [报告编制方法](report-methods-and-writing.md)和 [报告模板](../assets/report-template.md)撰写。结果章节直接回答每项要求，包含关键数字，不能只写“详见上文”。附件保留精确来源和计算；对影响具体结论的缺口不能只藏在附录。

新材料或修订影响数字时，定位相关要求、期间、表格、结果、图示、复核表与PDF并一起更新。执行 [最终复核](review-and-archive.md)，归档实际文件和手续状态，不承诺不存在的签发、签名或采信。
