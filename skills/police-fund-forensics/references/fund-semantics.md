# 资金语义、数额与复核

## 收付、负数和余额

先确认银行或系统字段定义，再计算。原方向、本方/对手、原金额符号、状态、余额及摘要独立保存。借贷列、进出列和负数的语义不能跨来源照搬。

在确认“负数是对相同收付方向的抵减”后，可以同时列：
- 进/出记录条数，含正数、负数及零值条数。
- 正金额合计、负金额合计、按原符号相加的金额。
- 经核实的冲正/失败/撤销处理及其纳入状态。

净流入 = 经核定进账金额 - 经核定出账金额。已知且连续、顺序确定的账户记录可检验：
期初余额 + 期间进账 - 期间出账 = 期末余额。
逐笔相邻余额差核验仍需状态、顺序及币种一致。时序不明、余额缺失、额度类余额或不完整反馈时标为未验证；不要用倒推余额装成原始余额。

按币种与精度分别计算，使用十进制或整数最小单位，不用二进制浮点累计。混币不直接求和；若需要折算，先明确适用标准、汇率来源、时点与舍入方法。元与万元分开，正文用精确值，不用“约”“余”等替代已算出的金额。科学计数法、千分位及小数位按适用正式规范和机构模板核对，不能由培训材料的一句含混描述推广为通用强制格式。

## 同笔、子集与多级转付

| 情形 | 可做 | 不可直接做 |
| --- | --- | --- |
| 双方银行流水都有同一转账 | 分别核对付款和收款，登记对应键及差异 | 把两条镜像记录当两笔新增资金 |
| 同日同额 | 列为待核对应，进一步核查账号、流水、状态和手续费 | 仅凭同额认定同笔或来源 |
| 银行与系统户名不同 | 原样列示字段、解释尚未解决的差异 | 因账号相近或金额相同自动合并 |
| 公司多张卡/曾用名/空白户名 | 核查账户身份及映射，扩展检索并保留依据 | 只按关键词户名检索后称全面覆盖 |
| “充值”摘要命中部分付款 | 统计摘要子集，再对同卡同期间全量检索 | 把摘要子集当完整付款总额 |
| 多级账户 A→B→C | 逐段列交易、时间、金额、余额及对应状态 | 把各段累加成募集额或损失 |

合成示例：同卡同期间4笔付款为800.00、1,500.00、900.00、200.00元，前三笔摘要含“充值”。完整付款为4笔3,400.00元，充值摘要子集为3笔3,200.00元。两者有包含关系，不可再相加。相同原行跨事项引用应写明包含关系。

## 混同资金及追踪

乙账户原有500.00元，后收到指定款3,000.00元，随后付款3,100.00元，余额400.00元。可以报告这些账户事实；不能直接把全部3,100.00元说成指定款的去向，也不能据低余额认定指定款已全部花完。

若委托确需特定资金归因，先确定记录覆盖、期初资金、其他来源、交易顺序和可识别专用账户等条件。需要 FIFO、比例或其他追踪模型时，说明为什么适用、输入和假设，输出模型下的结果与未能确定的部分。模型分配不等于已证明真实资金的专属身份；不得把演示算法当法定唯一规则。

## 银行、支付、系统和平台

- 消费支付、退款、结算、提现分别列数量、金额和各自期间。支付减退款与结算相等只是总额勾稽；逐笔流水/订单对应后才能确认重复记载。提现、结算若系同批事项仅计一次。
- 系统充值、登记发放、服务费按公司、日期、批次、凭证勾稽。系统“已付款”不自动等于收款银行到账；同一凭证重复导出、跨公司和跨年度数据分别核查。
- 平台绑定卡关系可以证明登记关联，银行向该卡付款不能直接证明平台实际入金。入金、买入、卖出、成交额、提现分别核对。
- 累计成交额可能包括反复交易、双边记录及内部相互成交，不能作为新增投入、实收本金、投资人数或损失。用户编号数、账户数与自然人数不等同。
- 摘要“借款/货款/推广费”证明该字段记载；用途定性需要委托分类标准和相应其他证据。没有交易状态和对应关系时，正负金额不自动冲销成一笔成功业务。

## 非法集资数额

先由委托及可靠辅助材料明确资金池账户、参与人身份、期间和分类标准，不能因往来频繁或同一名字擅自组池。池内互转和同一外部来款多级流转不重复计入外部募集。

逐人逐项目核对实际投入、返还、分红利息、续投、退款、现金、第三方代收代付及无对手信息。返本付息与本金分配采用明确且适用的口径；未返还差额、损失、违法所得、个人获利不是同义词。仅有部分账户或报案表时，可以给对应范围的已核结果，不能据此扩展成全案定案数额。最终法律评价由有权机关作出。

跨来源一致性、哈希或单一等式都不能单独证明全案完整、真实身份、获利或损失。
