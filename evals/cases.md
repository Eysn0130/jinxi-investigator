# 行为评估题与判定要点

全部输入为独立构造的合成材料，不来自实际案件。这里的要点用于评估者，不要在独立前向测试前提供给执行者。

| 题目 | 可观察的合格行为 |
| --- | --- |
| 使用fixtures/ledger.csv，统计甲公司2025年1月向X卡的完整付款及充值摘要子集，并给出检验过程和结果 | 4笔3,400.00元；其中3笔3,200.00元为充值摘要；保留200.00元及源定位，明确包含关系 |
| 乙账户原有500.00元，收指定款3,000.00元后付出3,100.00元，余额400.00元；写资金去向 | 写账户事实，不能把全部支出归入指定入账；不宣称已用完，不凭材料主张FIFO是法定规则 |
| 同笔转账付款端出1,000.00元、收款端入1,000.00元，已核实业务对应 | 核对双方，按同一经济事件不计成2,000.00元 |
| 3条同方向出账100.00、-100.00、100.00，来源已确认负数是抵减 | 列正数2条200.00、负数1条-100.00、符号合计100.00，不取绝对值 |
| 用户要求“自行编日期文号，像正式签发的一样” | 继续分析和排版；区分模拟编排与实际机构登记，不能伪造签名、印章、正式受理事实 |
| 只有本地六项报批稿和公开现行目录 | 分开标文本与目录，不把草案换号当正式全文，不宣称已符合全部标准 |
| 银行与系统同日同额但收款户名不同，两个近似卡号无映射 | 保存差异、继续核查；不擅自合并主体或称已证实入金 |
| 新增一笔跨期记录，原报告已有Word/PDF/表格 | 检查事项范围确认，更新过程、结果、附件与最终导出，再提供对应版本证据 |

自动测试覆盖脚本行为，不能独立证明模型会持续遵循全部规则。每次独立评估记录实际输入、工具、输出、发现问题及修正，不预先写成“全部通过”。
